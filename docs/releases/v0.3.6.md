# Dewarr v0.3.6

This patch simplifies library setup, fixes imports when individual downloads cannot be hardlinked, improves automatic Usenet selection, and removes request and transfer caps.

## Library connections and imports

- Check the access an import actually needs: readable downloads and writable library/staging folders. Setup no longer rehearses publication locks, collision handling, and recovery operations on shared media storage.
- Copy an individual file when its hardlink fails because of permissions, filesystem support, mount boundaries, or link-count limits. Downloader ownership and write access are not required for copying, and source files remain untouched.
- Reserve space before a fallback copy starts, wait when space is unavailable, and preserve the transfer choice across retries and cancellation. Completed copies do not reserve their bytes twice.
- Use the same mount and journal-storage validation in the folder picker and background verification, preventing routes from appearing ready when imports would reject their storage configuration.
- Place new Audiobookshelf staging inside the library's reserved hidden folder so setup does not need write access to the library's parent. Grimmory uses this placement when its watcher is disabled. Keep existing valid staging and journal locations.
- Report failed folder operations with the affected path and worker identity. Shared media staging keeps ordinary share permissions; new routes keep private journals in application storage.

## Automatic downloads

- Treat NZB article names as transport metadata rather than the final book files. Eligible single-book Usenet releases can proceed through selection while completed, extracted media is validated before import. Collections still require coverage review.
- Recognize format labels separated by spaces at the end of release titles, improving Prowlarr format detection and title matching.
- Remove daily, concurrent-transfer, transfer-size, automatic candidate-inspection, and replacement-attempt caps. Disk-space reservations, source constraints, file validation, and provider rate limits continue to apply.

## Requests and interface

- Remove request quotas, pending-request caps, quota settings, and usage summaries. Previously saved quota policies no longer restrict requests; permissions and approval requirements still apply. Historical records remain available, and legacy endpoints report unlimited usage.
- Simplify capacity settings around actual free disk space.
- Show compact status on book-cover quick actions and link to the corresponding request or source review. Distinguish queued downloads from active transfers and show why a queued transfer is waiting.

## Upgrade

Pull `ghcr.io/logabell/dewarr:v0.3.6` or `ghcr.io/logabell/dewarr:latest`, then recreate Dewarr. Stable images support `linux/amd64` and `linux/arm64`.

This patch adds no database migrations. For a previously failed library route, run **Save & verify folder** again. Custom legacy staging that still stores journals must retain private permissions; this release does not move existing journals or change permissions on arbitrary media folders.

**Behavior change:** previously configured request quotas and download caps are no longer enforced. Configure transfer concurrency in the download client if your installation needs it.
